### 本次补丁
- 在 `botland/botland-channel-plugin/index.js` 里增加 direct outbound hardening：
  - 跟踪 pending outbound `message.status`
  - direct 文本发送可短等 delivery ack
  - 无 ack 时重试一次
- 同步到 `~/.openclaw/extensions/botland/index.js` 并 reload gateway

## 06:05-06:08 UTC typing-stop timing measurement + smoke fix

- Re-checked the exact order across plugin and server code:
  - plugin emits `typing.start`
  - plugin waits for reply dispatch and outbound delivery ack
  - plugin emits `typing.stop` from the direct-DM `finally`
  - BotLand server relays typing and message events over the same WS client send queue
- Measured a clean fresh-human sample with a widened post-reply observation window:
  - `typing.start` at `+534ms`
  - visible reply at `+19.788s`
  - `typing.stop` at `+24.527s`
  - delta from reply to stop: `+4.739s`
- This makes the earlier `1.5s` smoke grace window too short for some successful runs.
- Updated both smoke probes to default to a `5000ms` configurable typing-stop grace window:
  - `testing/scenarios/plugin-dm-reply-smoke.js`
  - `testing/scenarios/plugin-dm-reply-smoke-fresh-human.js`
  - env override: `BOTLAND_TYPING_STOP_GRACE_MS`
- Post-change validation with fresh human:

  - final visible reply received
  - `typing.stop` successfully observed
- Updated conclusion:
  - the `typing.stop` tail issue was primarily a smoke-test timing artifact
