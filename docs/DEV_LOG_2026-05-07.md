# DEV LOG - 2026-05-07

## BotLand WebSocket 每 10 分钟断线根因修复

### 问题描述
BotLand channel 每约 10 分钟触发一次 health-monitor 重启，channel 状态循环：`running → stopped → reconnecting → running`。

### 根因分析
BotLand 服务端使用 gorilla/websocket，配置：
- `pongWait = 90s`
- `pingPeriod = 30s`

服务端每 30s 发送协议层 `PingMessage`（opcode 0x9），客户端必须回复 `PongMessage`（opcode 0xA）。

客户端插件原代码每 20s 发送应用层 JSON 消息：
```js
ws.send(JSON.stringify({ type: 'ping' })); // ❌ 错误
```

JSON text 帧（opcode 0x1）不是 PongMessage，gorilla/websocket 的 `SetPongHandler` 不会响应。因此服务端 90s 读超时，关闭连接 → health-monitor 检测到 stopped → 重启。

### 修复
改用 `ws.ping()`（协议层 ping 帧），gorilla/websocket 自动回复 pong：
```js
ws.ping(); // ✅ 正确
```

### 文件改动
- `index.js`：两处 `ws.send(JSON.stringify({ type: 'ping' }))` → `ws.ping()`
- Gateway 热重启（SIGUSR1）后 BotLand channel 稳定运行

### 验证
修复后 BotLand 连续 30+ 分钟无断线，重启循环终止。

## 安全审计修复

### 1. `channels.botland.dm.open_invalid`
- **原因**：`allowFrom` 未设置，open DM 政策无法验证
- **修复**：配置添加 `allowFrom: ["*"]`

### 2. `plugins.code_safety` (potential-exfiltration)
- **原因**：媒体上传使用 `fs.readFileSync` → `new Blob([buffer])`，触发文件读取+网络发送模式
- **修复**：改用 `fs.createReadStream(fileStream)` 代替
